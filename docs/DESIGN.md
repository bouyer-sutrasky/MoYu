# Superagent Workspace 设计访谈

## 已确认要求

- 项目首先面向个人使用，不建设多用户账号体系。
- Work 接入已部署在京东云的 superagent，支持发布任务和双向交互。
- 支持选择不同仓库。
- Chat 后续接入机器人，本期仅预留接口。
- 前端布局参考 ChatGPT，视觉变量沿用 DeepSeek Harness design tokens；登录机制独立设计。
- 登录采用 Passkey，不建设用户名密码注册流程。
- 桌面优先；手机主要查看进度和回答问题。
- 导航按仓库组织，提供跨仓库的运行中任务入口；已有任务不因切仓库改变归属。
- Work 可选择“直接执行 / 先讨论”，默认直接执行，并记住偏好。
- 默认交付到推送分支并创建 PR，由所有者审阅合并。
- 首次绑定及凭据全部丢失后的恢复，通过服务器命令生成短期一次性绑定码完成；初始化后关闭首次绑定入口。
- 登录长期保持，不因固定周期要求重新验证；主动退出、撤销或丢失浏览器会话数据后重新登录。浏览器可能自行清除或限制 Cookie，不能承诺设备永久免登录。
- 桌面使用约 260px 左栏、居中会话、底部输入框和默认收起的约 380px 右侧详情；详情包含变更、检查、交付。
- 默认跟随系统明暗主题，并允许手动切换；长日志默认折叠，待处理问题直接展示。
- 一条 Work 会话对应一个任务；超出范围或跨仓库的需求新建任务。
- 先讨论阶段仅允许读取、搜索和分析；修改项目及可能产生写入的执行须点击“按此方案开始执行”后启用，由权限状态强制约束。
- PR 待审阅时继续在原会话提出修改，更新同一 PR；合并后新需求创建关联的新任务。
- 第一版支持文字、GitHub Issue 链接、截图、日志和普通文本文件。
- superagent 使用专用 GitHub 账号；网页选择或输入其可访问的仓库，后台检查权限并准备执行环境。
- 新任务默认使用仓库默认分支，允许创建时选择其他分支，提交时记录实际起点 commit。
- 不同仓库允许并行，同仓库默认串行；等待人工回复或审阅不占执行名额。恢复执行仍须获得对应仓库名额。
- 停止保留任务现场和 PR，支持继续；不自动撤销已经发生的外部操作。仅实际停止后展示已停止。
- 保留 GitHub @ 入口，GitHub 发起的任务汇总到 Work，支持网页继续交互；同任务跨入口关联去重，按来源回复。
- 通知参考 ChatGPT 的活动中心、系统通知及分类设置；第一版仅网页打开时提供系统通知，不实现关闭网页后的 Web Push，重新打开后补看活动记录。
- 执行中补充消息尽快送入当前执行，在下一次可接收消息的步骤处理；区分已发送、待执行器读取、已读取，不承诺立即中断正在运行的命令。
- PR 关闭但未合并时标记“已关闭 · 未合并”，停止自动执行并保留现场；所有者可选择继续原任务或新建关联任务，不自动重开 PR。
- 每仓库独立 superagent 实例；服务器总内存 16GB，常态占用目标约 4GB，6GB 为常态预算，服务器空闲时允许整个新系统扩展至 8GB，包含平台、数据库及执行子进程。占用目标需要实测。
- 仓库按需启动，同时在线约两个实例；不强制常驻。网页提交或回复任务可请求启动实例。
- 正在执行的实例不自动休眠；优先休眠最久没有交互且无执行工作的实例。等待人工及审阅实例可保存状态后停止进程，随后重新启动恢复；两实例都忙则排队，人工回复优先于未开始的新任务。
- 仅在线实例监听 GitHub @；休眠仓库不因 GitHub @ 自动唤醒。界面显示监听暂停，唤醒后检查积压通知，补收能力须以实际版本验证。
- 超过常态预算前检查宿主机余量；资源不足时限制新任务启动、回收空闲实例。8GB 为整个系统的最高预算，仍不足时任务标记资源不足并保留现场，不无限重试。
- 第一版网页展示 diff、测试结果和 PR 链接；正式评论、批准及合并在 GitHub 完成。
- 会话、任务记录及附件默认保留并手动删除；运行中、已停止、受阻和待审阅工作目录不自动清理。
- 已合并任务工作目录保留 7 天后清理；清理前检查未提交及未推送修改，有未保存工作则跳过。不删除会话、报告或远端分支；设置页展示占用及清理结果。
- 短暂网络故障有限重试；服务重启后核对任务现场并恢复此前正在执行的任务。已停止、等待人工、待审阅和明确失败任务不自动启动；无法确认现场则受阻。
- 网页可为新任务选择 Harness 已配置模型，默认继承实例配置；已开始任务固定模型，不在本项目重复建设供应商与 API Key 管理。

## 设计树与第三轮问题

- 登录
  - 已确认 Passkey。
  - 已确认服务器一次性绑定码与恢复流程，长期保持登录。
  - 实现候选：服务端可撤销会话，浏览器持久 Cookie 自动续期；不依赖设备指纹，不将 Passkey 私钥作为会话凭证。
- 视觉
  - 已确认使用 design tokens；上游 packages/client/ui-theme 提供主题变量。
  - 候选实现改为 React + CSS Modules + clsx，消费语义变量；不叠加另一套组件视觉主题。
- 前端
  - 已确认桌面优先、仓库优先。
  - 已确认侧栏 / 会话 / 可折叠详情布局，详情标签与手机操作范围。
- Work
  - 已确认可选直接执行或先讨论，默认交付 PR。
  - 已确认单会话单任务、讨论到执行的显式转换、待审阅阶段追问继续原 PR、首版附件范围。
  - 已确认停止保留现场、跨仓库并行和同仓库串行。
  - 已确认通知首版范围、执行中补充消息时机及 PR 非合并关闭后的行为。
  - 已确认每仓库执行实例、数据保留及工作目录清理、失败恢复、网页审阅范围及模型选择。
- 仓库
  - 已确认网页添加、默认分支可选、GitHub @ 与 Web 双入口汇总。
  - 专用 GitHub 账号是 agent 执行身份，网页所有者仍使用独立 Passkey 身份；不把 agent 账号通知误当成人工新请求。
  - 已确认按需启动、休眠仓库不监听 @、空闲实例回收、全系统弹性预算与资源不足行为。

## 执行资源与待解决约束

在线实例数量与执行任务并发分别管理。初始设置最多两个在线仓库实例，每仓库一个执行名额；等待人工不占执行名额但仍可能占实例内存。
容器预算必须涵盖 worker 及其启动的构建、测试、后台进程；仅限制 Harness 主进程不等于限制任务资源。
停机仓库没有运行中的 GitHub Source，界面明确显示监听暂停；第一版不增加独立常驻 GitHub 监听器。
清理过工作目录的历史任务仍保留会话；再次工作需恢复 checkout 或新建关联任务，不能宣称原本地现场仍在。

## 通知方案

参考 https://learn.chatgpt.com/docs/notifications 的 Activity 与通知设置体验。
左侧铃铛打开全局活动列表，展示未读、运行中和等待回复的任务；支持点击定位任务与全部标为已读。
系统通知设置为从不 / 仅后台 / 总是，默认仅后台；需要回复、待审阅、已完成、失败按类别开关。普通进度不弹通知，同一事件去重。
第一版不实现 Service Worker 与 Web Push 通知。网页打开但在后台时可通知，取决于浏览器权限及系统设置；网页关闭后不承诺送达，重新打开后从持久化活动记录补看。系统弹窗外观由操作系统决定。
