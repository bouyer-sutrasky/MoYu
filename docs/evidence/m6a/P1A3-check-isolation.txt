## 3. 逐项判定

### 3.1 环境隔离 —— 已实现

`runChecks` 不再传 `process.env`，改为白名单 `CHECK_ENV_KEYS = PATH, HOME, TMPDIR, LANG, LC_ALL`
（`apps/supervisor/src/review.ts` 的 `checkEnvironment()`；LANG/LC_ALL 缺省补 `C`）。
`bash -lc` 仍会执行 `/etc/profile`，实测可能重写 `PATH`/`LANG`（绿段测试因此断言 `HOME`、`TMPDIR` 精确值、
`PATH` 含父进程值、`LANG`/`LC_ALL` 存在），但父进程注入的哨兵变量一个都到不了子进程。

### 3.2 身份隔离 —— 未实现（原因与后续归属）

平台 supervisor 以非 root 专用用户运行且禁止提权，进程内无法切换 uid/gid：

$ sed -n '9,16p' deploy/systemd/moyu-m5b-supervisor.service
[Service]
Type=simple
User=moyu-m5b
Group=moyu-m5b
WorkingDirectory=/opt/moyu/m5b
EnvironmentFile=/etc/moyu/m5b/supervisor.env
Slice=moyu-m5b.slice
# Let the supervisor create instance cgroups inside the delegated subtree.

因此检查命令仍以 supervisor 用户（`moyu-m5b`）身份运行；本轮提供的是环境白名单 + 工作目录
（`cwd` = 该 ticket 的 worktree，未变）。要做「独立低权检查身份」，需要一次特权启动器改造
（单独 systemd unit/socket + 预置低权用户 + worktree 所有权/写权限设计），不属于 #57 本轮范围。
归属：所有者决定是否另立一项；在此之前不声称身份已隔离。

### 3.3 超时回收 —— 已实现

`runCommand` 新增 `ownProcessGroup`：检查命令以 `detached: true` 起成独立进程组，超时时
`process.kill(-pid, 'SIGKILL')` 回收整组（失败才退回直接 kill）。红段里孙进程 `/proc/<pid>/stat`
状态为 `S`（存活），绿段断言其状态为 `Z` 或已消失。

### 3.4 并发门控 —— 已实现

`checks()` 改为在任何 await 之前 `runningChecks.add(repositoryId)`，`finally` 释放；
红段第二个并发请求拿到完整结果（命令执行两次），绿段第二个请求立即以 409
「该仓库已有检查正在运行，请等它结束」拒绝，计数文件只有一次 `x`。
