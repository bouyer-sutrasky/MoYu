## 0. 为什么此前被挡住，以及本轮改了什么

此前 profile 只有模型条目、没有声明输入模态，LLM 层解析出的 `input` 回落到默认 `["text"]`，
`read_image` 在工具入口直接拒绝（`model "..." does not declare image input`）。

本轮先实测：`commandcode` 网关下的 `deepseek/deepseek-v4.1-flash` **本身接受图像输入**（见 §6.1
探针：宽高、Row 文本、色块都读对；token 有一个 `O/0` 字形歧义，不影响能力判断）。因此在隔离
profile 的模型条目补上：

```yaml
            input:
              - text
              - image
```

这不是“给不支持图像的模型硬写模态”：模型/端点在写声明之前已用真实图像请求验证；没有换模型、没有
新增端点、没有使用外部 OCR。隔离 profile 全文片段见 §5。

## 6. 可复现的命令（本轮实际执行）

1. 探针（先证明模型本身接受图像，再写声明；脚本已提交为
   `scripts/m6a/l113-vision-probe.py`）：

   ```bash
   $ python3 scripts/m6a/l113-vision-probe.py /tmp/probe.png
   finish: stop usage: {'prompt_tokens': 680, 'total_tokens': 1002, 'completion_tokens': 322, 'completion_tokens_details': {'reasoning_tokens': 284}}
   WIDTH=1200
   HEIGHT=800
   TOKEN=Q7K-8842-M0YU
   ROW=alpha bravo charlie delta
   BOX=red
   exit code: 0
   ```

   该探针截图（1200×800）的 token 真值是 `Q7K-8842-MOYU`；模型把字母 `O` 读成数字 `0`，
   其余宽高、Row 文本、色块均正确。这足以证明模型**接受图像输入**，也说明最终验收截图应避免
   `O/0` 这类易混字形——本轮最终 token 用 `7Q3K-8842-L113`（无 O/0）。

2. 隔离 profile：复制 `/root/.dsh-m5/profiles/m5b` 的 `package.json`/`cordis.yml` 与
   `cordis.patch.yml`，要点：`webserver.port=__DSH_PORT__`、`dsh-superagent.stateDir=__STATE_DIR__`、
   模型条目加 `input: [text, image]`，`node_modules/dsh-superagent -> /root/src/upstream/l113-build1`；
   把 `/root/.dsh-m5/.credentials.yaml`（含 `COMMAND_CODE_API_KEY`）复制到隔离 `DSH_HOME`，权限 0600。

3. 隔离库：`createdb moyu_m6a_image` + `DATABASE_URL=… pnpm --filter @moyu/db db:migrate`；seed 一个
   owner、repository、浏览器 session。

4. supervisor（`apps/supervisor/dist/main.js`）：`DSH_HOME=/tmp/m6a-image-run/dsh-home`,
   `PROFILE_TEMPLATE_DIR=/tmp/m6a-image-run/profile-template`,
   `EXECUTOR_MODEL=commandcode/deepseek/deepseek-v4.1-flash`, pinned instance
   `{profile: imagetest, dshPort: 4801, bridgePort: 4800}`；`prepare` + `wake` 后实例
   `online/listening`。

5. API（4802）与 dispatcher（同一隔离库，`RUNTIME_CREDENTIALS_DIR=/tmp/m6a-image-run/creds`）。

6. 通过真实 API 上传截图并发送消息：`POST /api/v1/conversations` →
   `POST …/attachments`（multipart `file`）→ `POST …/messages`（`attachmentIds`）。

7. 从 `DSH_HOME/sessions/.../worker-<ticket>/session.v4.jsonl.zstd` 解压会话，取 `read_image`
   原始行；从 `messages` 表取 runtime 返回的 result 正文。

截图与 HTML 源：本轮 `l113-image-reading-card.html`（提交的副本）用
`chromium --headless=new --no-sandbox --disable-gpu --hide-scrollbars --force-device-scale-factor=1 --window-size=1360,900 --screenshot=… file://…/card.html`
生成；提交的 PNG sha256 见 §2。

## 7. 边界与未验证项

1. 本轮只在隔离 profile（`/tmp/m6a-image-run/dsh-home/profiles/imagetest`）里加了 `input` 声明，
   **没有**改共享 `m5b` 实例（边界要求），也没有改 `/root/.dsh/profiles/superagent`（bootstrap 运行中）。
   要让生产/共享执行器具备该能力，需要所有者把同一行
   `input: [text, image]` 加到对应 profile 的 `deepseek/deepseek-v4.1-flash` 模型条目并重启该实例。
   该声明已由 §6.1 的真实图像请求验证，不是“硬写”。
2. 截图为 Chromium 渲染的 acceptance card，不是某个业务页面的截图；它包含可辨识文字与两个纯色块，
   满足“看到像素”的判据，但不等价于对真实业务 UI 截图的验收。
3. 模型为核对颜色额外解码了 PNG 像素；文字转写来自 `read_image`，没有外部 OCR。若复核者要求
   “颜色也必须纯靠视觉”，本证据的颜色项不满足该更严格要求（尺寸与文字项仍满足）。
4. 限制：报告说明的“图片像素尺寸”与实际一致；模型没有给出截图之外的信息。
