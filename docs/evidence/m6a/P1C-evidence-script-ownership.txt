## 3. 两处「按谁」的改法

### 3.1 按命令行杀 dispatcher（原 A3 收尾）

- 旧：`ps -eo pid,args | grep 'dispatcher/dist/main[.]js' | … | kill` —— 会杀掉任何同名 dispatcher。
- 新：A3 启动 dispatcher 时走 `start_owned dispatcher …`，把 pid 写进 `$RUN/pids/dispatcher.pid`，进程环境里带
  `M6A_RUN_ID=<本次 run 的唯一 id>`；收尾改调 `stop_dispatcher` → `stop_owned dispatcher`。

### 3.2 按端口杀监听者（EXIT trap）

- 旧：`ss -ltnp | grep ':4620|:4621|:4690|:4699' | … | kill` —— 会杀掉任何占着这些端口的进程。
- 新：所有服务（stub Bridge、supervisor、after API、before API、dispatcher）都经 `start_owned` 启动并记录
  `$RUN/pids/<name>.pid`；EXIT trap 只调 `cleanup_run_processes` → `stop_owned_services` → 逐个 `stop_owned`。

`stop_owned` 的信号前先做归属证明：`grep -qzxF "$MARKER" /proc/<pid>/environ`（`MARKER` 是本次 run 的
`M6A_RUN_ID`）；证明通过才 `kill -TERM -- -<pid>`（整进程组，服务是 `setsid` 起的 session leader），
超时再 `SIGKILL`。进程已消失或环境读不到时一律不动。`start_owned` 在启动时同样校验一次：pid 文件写完后
若 `/proc/<pid>/environ` 没有本次标记就直接失败，不再继续跑。
