## 3. 拒绝的类别与合法路径

修复点：`locateTicketWorktree` 先 `realpath` 解析 `worktreeRoot` 与 `worktreeRoot/<profile>`，
再用 `path.relative` 判断是否严格位于边界内（不用字符串 `startsWith`，因此 `/root/src/aaa-evil`
不会被当成 `/root/src/aaa` 的子路径）；每个匹配候选同样先 `realpath` 再判边界，越界即拒绝，
不会 `stat` 越界目标；返回的 `directory` 是解析后的真实路径。

| 类别 | 测试 | 红 | 绿 |
| --- | --- | --- | --- |
| ticket 目录直接符号链接到边界外 | `refuses a ticket directory symlinked outside the worktree root` | available（失败） | unavailable + 边界原因 |
| profile 目录符号链接到边界外（父目录） | `refuses a profile directory symlinked outside the worktree root` | available（失败） | unavailable + 边界原因 |
| profile 用 `..` 爬出边界 | `refuses a profile path that climbs out of the worktree root with ..` | available（失败） | unavailable + 边界原因 |
| 符号链接套符号链接再出界 | `refuses a symlink chain that reaches outside the worktree root` | available（失败） | unavailable + 边界原因 |
| 正常 `WORKTREE_ROOT/<profile>/<ticket 前缀目录>` | `still locates a real directory inside the worktree root`（红段即绿） | available | available |

「没读到边界外」的判据：边界外目录里放 `outside-sentinel.txt`（内容 `top secret`），四条拒绝用例都断言
`JSON.stringify(result)` 不含哨兵文件名（也不含其内容），返回值只有 `state/directory/reason/profile`；
不是只看返回值是否为空。

## 4. 判定与边界

- 生产路径：`apps/supervisor/src/review.ts` 的 `locateTicketWorktree`，`createReviewService.resolve/changes/checks`
  都经由它拿到目录；浏览器自动采集走同一条路径。
- 行为变化：可用时返回解析后的真实路径（原来是 join 出来的词法路径），后续 git 调用不会被中途改写的链接带偏。
- 未动：P1-A 其余两刀（检查子进程最小环境 + 低权身份、超时按进程组回收）、并发门控竞态、P1-B/P1-C 等。
- 未验证：推送后的 GitHub CI（本轮结束时尚未触发）；A1–A8 整套证据尚未在新 head 重跑。
- 复现：`cd apps/supervisor && /opt/moyu-node24/bin/pnpm exec vitest run test/review.test.ts`。
