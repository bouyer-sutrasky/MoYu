## 现场编排的必要修正（随补丁提供，不改生产行为）

- `item5-restart.sh` / `item5-awaiting-review.sh`：PG 重启前先停 dispatcher/API/supervisor，
  PG 回来后用 `stack.sh services-up` 重建 transient units；否则 supervisor 的 pg Pool 会因
  “terminating connection due to administrator command” 未处理错误而退出。
- `item5-restart.sh`：恢复回合的 worker 延迟置 0，使后续真实输入的游标推进在单次现场运行
  内可观测；中断仍然发生在原 live 回合的 600s 模型调用上。
- `item5-awaiting-review.sh`：`pr-number.txt` 改为 0644（矩阵身份要读），重启前后用完整
  PR JSON 比较绑定；新增重启块与“无新 Assignment/operation/delivery”断言。
- `stack.sh` 新增 `services-up` 与 `reset-state`：前者在不重置数据库/票状态的情况下重建
  transient units，后者在没有第二次凭据 gate 的情况下重建数据库与运行时状态，供场景之间复位。

## 未验证

1. 多仓库同时重启、`discussing` / `waiting_input` 回合。
2. 宿主真实重启（systemd/OS reboot）而非进程级重启；本轮是进程与两个数据库的隔离重启。
3. 运行时孤儿进程长期存活时 replacement 会继续等待，需等其退出后的下一次 launch；
   本轮没有注入长期孤儿。
